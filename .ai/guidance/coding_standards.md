# Coding standards

Condensed from [CODING_STANDARDS.md](../../CODING_STANDARDS.md) and [CONTRIBUTING.md](../../CONTRIBUTING.md), which stay the human-facing sources. Where they disagree with the code, the code and `.golangci.yml` win; say so in the PR.

## Language and tooling

- Go `1.26.0` minimum (`go.mod`); CI builds and tests on `1.26.x` and `stable`, on Linux and macOS. `go mod tidy -diff` must be clean in the root module and in every nested module (`make check-nested-modules`).
- Formatting: `gofmt -s` (CI fails on any file `gofmt -s -l .` lists). `make fmt` rewrites files.
- Lint: golangci-lint v2 (`.golangci.yml`, CI pins `v2.12.2`) with `errcheck`, `govet`, `ineffassign`, `misspell`, `staticcheck`, `unused`, and formatters `gofmt`, `goimports`. `examples/` is excluded from linting. `make lint` silently skips when golangci-lint is not installed, so check that it actually ran.
- Imports in three groups separated by a blank line: standard library, third party, this module (`github.com/mediusfy/modulex/...`).

## Module layout

- The root package `modulex` is the core: `Manager`, module wiring, supervised tasks, health and readiness. It must not import any adapter package (`nats`, `rabbitmq`, `watermill`, `otel`, `chi`, `httpx`, `grpc`); `make check-consumer-boundary` enforces this for `modulex.go`, `wire.go` and `diagnostics.go`.
- Adapters and agent-support packages are separate, optional packages in this module. Executables and heavier tools are nested Go modules with their own `go.mod` (`tools/agentcli`, `tools/mcpserver`, `tools/modboundary`, `tools/provenanceci`, `tools/scaffold`, `examples/external-consumer`, `services/prreview`). A change to the root API must keep them building.
- Feature modules (in `examples/` and in consumers) follow `domain/`, `ports/`, `service/`, `adapters/`, `module.go` (README "Directory Standards"). Features depend on each other's `ports/` only; `make check-module-boundary` enforces it on `examples/deployment`.
- The public API is a compatibility surface ([COMPATIBILITY.md](../../COMPATIBILITY.md)). `make check-api-compat` reports changes since the latest tag; v0 minor releases may break it, but every break gets a `CHANGELOG.md` entry.

## Errors

- Exported sentinel errors are package-level `var ErrXxx = errors.New("...")` values that callers match with `errors.Is` (for example `ErrModuleNil` in `modulex.go`; the full list is in `docs/planning/error-handling-guide.md`). `CODING_STANDARDS.md` describes a typed `type Error string` pattern instead; the library code does not use it, so follow the package you are in. Wrap with `%w` so `errors.Is` keeps working.
- Constructors are `NewXxx(deps...) (*Xxx, error)` and validate their inputs. No package-level mutable state; dependencies come in through constructors or struct fields.

## Constants, logging and tracing

- Repeated log keys and trace attribute names are `const` blocks at the top of the file (`logKeyXxx`, `traceAttrXxx`), as in `nats/` and `rabbitmq/`. New code follows that; not every older file does yet.
- Log with `log/slog` only, using `LogAttrs` and named key constants. No `log` or `fmt.Print` in library code.
- Public methods that do work start a span, record errors and `defer span.End()`. Background work goes through the trace-safe task helpers so context and spans are not lost (README "Preventing Telemetry Gaps").

## Concurrency

- Long-running goroutines are owned by the lifecycle (`Start`/`Stop`) or by supervised tasks and `workerpool`, never fire-and-forget. Use `errgroup` to run several and wait for all.
- Every blocking call takes a `context.Context` and returns when it is cancelled. Shutdown runs in reverse dependency order.

## Tests and mocks

- Table-driven tests with `t.Run`. `modtest` holds reusable lifecycle, health, cancellation and rollback checks for modules.
- Mocks in `mocks/` are generated by mockery from `.mockery.yaml`; after changing an interface run `mockery --config .mockery.yaml` and commit the result. Do not hand-edit generated mocks.

## Generated and protected files

- `AGENTS.md` and `CLAUDE.md` are generated from `modulex.agent.yaml` by `modulex agent generate` (`agentdocs`). Do not edit them by hand; change the contract and regenerate. `contract/testdata/modulex.agent.example.yaml` must stay identical to the root contract (`TestRootContract_MatchesExample`).
- Protected paths need explicit human approval: `.github/workflows/*.yml`, `.github/CODEOWNERS`, `CODEOWNERS`, `SECURITY.md`, `go.mod` retract directives and released `CHANGELOG.md` sections (`docs/planning/agent-safety-policy.md`).

## Changelog

- Add an entry under `## [Unreleased]` in `CHANGELOG.md` (Keep a Changelog format). `scripts/check-changelog.sh` fails a PR that changes anything outside `.github/` and `go.mod`/`go.sum` without touching `CHANGELOG.md`.
